# Reusable AI Workflow Template

Version: 1.0

Purpose:
Define the standard workflow for collaborating with AI assistants on long-running projects. This template ensures consistency, traceability, and high-quality documentation regardless of the project domain.

---

# Workflow Overview

Every project follows the same lifecycle:

1. Discovery
2. Planning
3. Documentation
4. Review
5. Refinement
6. Approval
7. Implementation
8. Validation
9. Publication
10. Maintenance

---

# Phase 1 — Discovery

Objective

Understand the problem before proposing solutions.

Deliverables

- Problem statement
- Background
- Constraints
- Assumptions
- Existing assets
- Success criteria

Exit Criteria

The problem is clearly defined and agreed upon.

---

# Phase 2 — Planning

Objective

Design the project before implementation begins.

Deliverables

- Scope
- Architecture
- Milestones
- Risks
- Dependencies
- Timeline (if applicable)

Exit Criteria

A documented execution plan exists.

---

# Phase 3 — Documentation

Objective

Create high-quality documentation before or alongside implementation.

Deliverables may include

- Technical specifications
- Architecture documents
- Workflow documents
- Decision records
- Project summaries
- Portfolio documentation
- Research documentation

Documentation Principles

- Clear
- Complete
- Structured
- Reusable
- Version controlled

---

# Phase 4 — Review

Objective

Evaluate documentation for quality and consistency.

Review Checklist

- Technically accurate
- Consistent with canonical identity
- Free of contradictions
- Appropriate for intended audience
- Complete
- Logically organized

Exit Criteria

Issues are identified before refinement.

---

# Phase 5 — Refinement

Objective

Improve documentation based on review findings.

Activities

- Clarify ambiguous sections
- Remove inconsistencies
- Improve explanations
- Simplify unnecessary complexity
- Update affected documents

Exit Criteria

Documentation is publication-ready.

---

# Phase 6 — Approval

Objective

Confirm that the work is complete.

Approval Questions

- Does it meet the original objective?
- Is the quality acceptable?
- Is it consistent with the repository?
- Is it ready for implementation or publication?

Only approved work progresses.

---

# Phase 7 — Implementation

Objective

Build or execute the approved design.

Examples

- Software development
- Machine learning implementation
- Data engineering
- Research execution
- Website development

Implementation should not redefine approved documentation without recording changes.

---

# Phase 8 — Validation

Objective

Verify that implementation matches the documented design.

Validation includes

- Functional testing
- Technical verification
- Consistency checks
- Performance evaluation
- Documentation updates where required

---

# Phase 9 — Publication

Objective

Prepare outputs for external audiences.

Possible Outputs

- GitHub repositories
- Portfolio projects
- Presentations
- Publications
- Reports
- Demonstrations

Published artifacts become part of the identity ecosystem governed by WF-000.

---

# Phase 10 — Maintenance

Objective

Keep project artifacts accurate over time.

Maintenance Activities

- Periodic review
- Documentation updates
- Link verification
- Dependency updates
- Portfolio synchronization

---

# AI Collaboration Rules

Every AI assistant should:

- Read the provided context package before beginning work.
- Treat canonical identity documents as authoritative.
- Avoid inventing experience or achievements.
- Produce structured, reusable documentation.
- Explain important design decisions.
- Preserve consistency across project artifacts.

---

# Standard Inputs

Every new project should begin with:

- Project objective
- Intended audience
- Available resources
- Constraints
- Success criteria
- Relevant canonical documents

---

# Standard Outputs

Each completed project should produce, where applicable:

- Project summary
- Technical documentation
- Architecture documentation
- Implementation artifacts
- Presentation materials
- Portfolio-ready documentation
- Lessons learned

---

# Repository Integration

This workflow complements:

- WF-000 — Academic & Professional Identity Stack
- Career Identity documents
- Claude Context Package

Projects may extend this workflow but should not bypass it without documented justification.

---

# Continuous Improvement

After project completion, record:

- What worked well
- What did not work
- Lessons learned
- Process improvements

Update this workflow only when improvements are broadly applicable across future projects.
