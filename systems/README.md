# Systems Layer

Version: 1.0
Status: Active

---

# Purpose

The Systems Layer documents repeatable operating systems that govern how work is performed across the Kingsley Operating System (KOS).

Unlike workflows, which describe how a specific project was executed, systems define ongoing methods of operation that span multiple projects and evolve over time.

---

# Relationship to Other Layers

The repository distinguishes clearly between identity, systems, workflows, and knowledge.

| Layer | Purpose |
|--------|---------|
| Identity | Defines who I am professionally. |
| Systems | Defines how I consistently operate. |
| Workflows | Documents how individual projects were executed. |
| Knowledge | Preserves reusable insights extracted from completed work. |

---

# Examples of Systems

Examples include, but are not limited to:

- Career Management System
- Research Management System
- Learning System
- Portfolio Management System
- AI Collaboration System
- Documentation System
- Decision-Making System
- Continuous Improvement System

---

# Design Principles

A system should:

- solve a recurring problem;
- be reusable across multiple projects;
- define repeatable processes;
- evolve through version control;
- improve over time through documented refinement.

---

# Relationship to Workflows

A workflow records execution.

A system governs execution.

Example:

```
Career Management System
        │
        ▼
WF-001
WF-002
WF-003
```

The system provides the operating rules.

Individual workflows apply those rules to specific projects.

---

# Rule

If the document explains **how I repeatedly operate**, it belongs in the Systems Layer.

If it explains **how one project was completed**, it belongs in the Workflow Layer.
